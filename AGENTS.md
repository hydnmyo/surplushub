## Working Agreement — parallel agent sprint

Four agents are building the order and payment flow at the same time on separate machines. These
rules exist so the four branches merge cleanly. Read them before writing any code.

### Never touch these files

They are shared contracts or generated output. Editing them will conflict with another agent:

- `src/lib/data.ts` — the 1,500-line seed dataset. Nobody edits it this sprint.
- `src/lib/fees.ts` — the fee model. Frozen.
- `src/lib/orders.ts` — order types, statuses, `SEED_ORDERS`. Frozen.
- `src/components/orders/FeeBreakdown.tsx` — shared money breakdown. Frozen.
- `src/routeTree.gen.ts` — generated by TanStack Router.
- `src/routes/__root.tsx` — the provider tree.

### Never do these things

- **Do not create a route file.** Every route this sprint already exists as a stub. If you think you
  need another one, stop and ask the integrator — adding one regenerates `routeTree.gen.ts` and
  conflicts with every other branch.
- **Do not run `npm run format`, `prettier --write .`, or `eslint --fix` across the repo.** The repo
  was formatted once in the seed commit. A repo-wide reformat touches ~100 files and destroys every
  other agent's diff. Format only the files you own.
- **Do not hardcode a fee percentage.** Always call `calculateOrderTotals()` from `src/lib/fees.ts`.
  The rates live in exactly one place so they can be changed in one edit.
- **Do not assign `order.status` directly.** Guard every change with `canTransition()` from
  `src/lib/orders.ts`.

### Money rules

- The fee base is the **negotiated material price only**. Delivery and tax are passed through and are
  never multiplied by a fee rate.
- Seller pays a 2% success fee; buyer pays a 1% service fee.
- Canonical worked example, which must render exactly on every surface that shows it:
  material `1,000,000 MMK` → buyer pays `1,010,000` · seller receives `980,000` · platform gross
  `30,000`.

### Workflow

1. `git checkout main && git pull origin main` before you start.
2. Branch as `feat/<track>-<short-name>`, e.g. `feat/b-checkout-payment`.
3. Edit only the files your issue lists under "Files you own".
4. Before opening a PR: `npx tsc --noEmit` must be clean, and
   `npx eslint <only your files>` must have no errors.
5. Open one PR per issue against `main`. **Do not merge it yourself** — the integrator merges in a
   fixed order to keep conflicts resolvable.

### Data layer

Order state is **localStorage only** this sprint (`surplushub.orders.v1`, via
`src/components/orders/OrderProvider.tsx`). Do not add Supabase tables, migrations or queries for
orders — that is a later phase.
